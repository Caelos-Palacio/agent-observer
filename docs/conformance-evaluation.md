# Optional structured conformance evaluation

This offline evaluator compares external rubric labels with host-supplied verdict codes. It runs no model, connects to no provider, and changes no permissions. Existing review and logging behavior is unchanged. Use `npm run evaluate:conformance` for the new public synthetic corpus, or `node src/cli.mjs evaluate-conformance --file METADATA_JSON` for an explicit file. The optional SDK export is `agent-observer-local/evaluation` (`evaluateConformance`).

The input contains `rubric` and `runs` only. Rubric schema version 1 uses opaque 32-character hexadecimal rubric/case IDs, an integer version, expected decision (`allow`, `deny`, `clarify` or unknown), approval state and applicability of argument/order/effect checks. Runs contain opaque IDs and observations: decision plus `match`, `mismatch` or `unknown` verdicts. Argument checks describe a verdict supplied by a trusted external observer; argument values are never accepted. No prompts, prose, outputs, credentials, paths, resource names or agent identities belong in this schema. This allowlist rejects extra fields; it cannot establish that supplied codes are truthful or safely derived. Do not encode personal data in IDs.

Safety components count unauthorized allows, allows with missing approval, and argument/order/effect mismatches. Utility components count authorized denials, unnecessary clarification, missed clarification and authorized completion. Lower is preferable for violations; higher is preferable for completion. There is no combined score or ranking. A deny-all policy can have zero unauthorized allows while denying every authorized task.

Each component reports numerator, known denominator, unknown slots, non-applicable slots, rate and at most 20 opaque witnesses. Rates with zero denominators are `null`. Missing oracle labels or applicability remain unknown. Cancelled, uncertain, unknown and absent observations remain separate from denial and clarification. Completion requires allow plus externally verified effects and all applicable checks matching; known mismatches disprove completion, while missing required evidence leaves it unknown. These counts describe case/run slots, not independent statistical trials. Runs of the same cases can be correlated; no confidence interval or generalization is claimed.

The versioned fixture `fixtures/conformance-v1.json` contains 17 newly authored synthetic cases. Test expectations were separately enumerated as literal counts, rather than generated by the evaluator. This is a reviewable consistency oracle, not independently established semantic truth. Two runs can agree and both violate a supplied rubric; the rubric itself can also be wrong. The corpus checks accounting and distinctions, not natural-language understanding or real tool execution. It does not reuse private research cases, run archived results, or claim new provider/token/billing measurements.

The CLI accepts only an explicit regular single-link file (no final symlink), at most 512 KiB, opened read-only. Output is bounded at 2 MiB; errors withhold input and paths. Schema limits are 100 cases, 20 runs and 100 observations per run. SDK callers supply objects directly and must control their own ingestion. No telemetry source is discovered or enabled. External controllers must decide rubric labels and verdicts separately from agent explanations; logs and evaluation outputs never grant authority.
